#+title: overlays

Parking lot for temporary out-of-tree patches: when something in nixpkgs (or a package built from a flake input) breaks and the fix hasn't landed upstream yet, the workaround lives here as an overlay until a flake update makes it obsolete.

Most of the time nothing in this directory is wired in. An unreferenced overlay is dormant, not dead — don't delete a file just because nothing imports it. Delete it when its removal condition is met.

* Enabling an overlay

Overlays are applied per-host in =flake.nix= through the =overlays= argument of =mkHost=:

#+begin_src nix
hyperion = mkHost ./nix/hosts/hyperion/configuration.nix {
  overlays = [
    inputs.niri.overlays.default
    (import ./nix/overlays/niri_20260728.nix)
  ];
};
#+end_src

Order matters when a dated overlay patches a package that itself comes from an input overlay: the input overlay goes first so that =prev.<pkg>= inside the dated overlay is the package being patched.

Every host imports =nix/modules/temporary-overlays.nix=, which reports each applied overlay through the module system's =warnings=, so wiring an overlay into a host needs nothing more. A package set built outside the module system has no =warnings=: attach the report to the output that consumes the overlaid packages instead, as =flake.nix= does for the devShell with =warnTemporaryOverlays=.

* Conventions

Follow the pattern set by =niri_20260728.nix= (undated files here predate these conventions):

- Dated filename :: =<package>_<YYYYMMDD>.nix=, dated to the overlay's creation. The date makes staleness visible at a glance, and the file stem doubles as the overlay's =id=, which every warning names.

  An overlay that needs more than the one =.nix= file — a patch to apply, a file to substitute in — becomes a directory =<package>_<YYYYMMDD>/= holding a =default.nix= alongside its supporting files. The stem, and so the =id=, is unchanged; only the import loses its extension:

  #+begin_src nix
  (import ./nix/overlays/nushell_polars_20260805)
  #+end_src

  Keep the supporting files named for their role (=ethnum.patch=), not re-stating the overlay name — the directory already carries it.

- Header comment explaining the issue :: every overlay opens with a comment block stating:
  1. the symptom — what stopped building, quoting the literal error message;
  2. the root cause;
  3. the upstream fix it backports or mirrors, with links (nixpkgs PR or issue, upstream bug tracker);
  4. the removal condition — "Remove once ...", with a [[https://nixpk.gs/pr-tracker.html][pr-tracker]] link when waiting on a nixpkgs PR to reach the pinned channel.

- Built with =mkTemporaryOverlay= :: the file evaluates to =(import ../lib/temporary-overlay.nix).mkTemporaryOverlay= applied to the overlay's =id=, the =attrPath= it patches, and a =fix= function of =final: prev:= returning the check and the patch:

  #+begin_src nix
  (import ../lib/temporary-overlay.nix).mkTemporaryOverlay {
    id = "some_pkg_20260801";
    attrPath = ["some-pkg"];
    fix = _final: prev: {
      needed = prev.some-pkg.version == "1.2.3";
      reason = "some-pkg ${prev.some-pkg.version}";
      patched = prev.some-pkg.overrideAttrs (_old: {/* ... */});
    };
  }
  #+end_src

  While =needed= holds, the attribute is replaced by =patched= and each evaluation warns =temporary overlay for some-pkg enabled: some_pkg_20260801=. Once it stops holding, the attribute passes through untouched and the warning flips to a removal reminder quoting =reason=. Nested attributes take the full path (=["nushellPlugins" "polars"]=); =applies = false= makes the overlay inert and silent where the breakage never reached, such as another platform.

  Compute =needed= from =prev= whenever the removal condition is mechanically checkable — =niri_20260728.nix= reads niri's =Cargo.lock= and nixpkgs' =libdisplay-info= version at eval time. When it can't be computed in Nix (e.g. "the pinned nixpkgs now contains PR #NNNNN"), set =needed = true=: the header's removal condition plus the enabled-warning on every eval is the reminder to go check the tracker. When the deciding expression lives in a flake input rather than =prev=, make the file a function of that input returning the overlay, as =sops_install_secrets_20260917.nix= does.

  Don't add =lib.warn= on top. A warning on the patched attribute goes silent whenever nothing forces that attribute — including once the broken consumer is fixed, exactly when it should become a removal reminder — and a warning on the overlay's attrset repeats for every package set nixpkgs re-applies overlays to.

- Stay scoped :: override only the target package. If the fix needs an older library, inject it into that package alone rather than replacing the library globally — =niri_20260728.nix= builds a private =libdisplay-info 0.3= for niri while every other consumer keeps 0.4.
